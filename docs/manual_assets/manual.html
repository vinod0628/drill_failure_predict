1. Overview of the system

The system predicts where and why a drillhole is likely to fail and gives the driller a fixed set of countermeasures. It learns from past holes drilled in many areas (successful and failed) and applies what it learned to a new area, where an approximate geological model exists. The past areas share rock types with the new area, but not formations, and formation thickness changes strongly even inside one area. Lessons therefore transfer only through what the rock is (its mechanical and karst properties) and where it sits relative to its contacts - never through formation names or coordinates.

Figure 1. Data flow: geological model, live hole and history feed the feature engine; the models, rules and evidence produce levels, zones, reasons and measures.

The system asks two linked questions (spec 1.1): first, will the hole meet a hazard here (a cavity, a fault zone, hard or broken rock)? Model H answers it. Second, will it fail here under these drilling conditions? Model A answers it ahead of the bit, Model B while drilling. Fixed rules R1 - R8 catch clear physical signs even when a model is wrong. All of them combine into one alarm level per metre.

3. Data preparation and construction

This chapter explains what data the system needs, how to prepare it, where it is stored and how the per-metre training table is built from it. Good data preparation matters more than any model setting: the models can only learn what the records show.

All records are tables of the workspace's project database (Settings → Database): the SQLite file geodatabase.sqlite in the workspace folder (default; nothing to install) or one MySQL database shared by several users. How to code the history

  • Result. success = reached its final depth; failed = abandoned (or the planned target given up) because of a problem; in progress = being drilled (final depth = current bit depth); planned = not started.
  • Failure (one row per failed hole): the depth where the hole was lost or abandoned, the failure code of the cause (map your own fail codes once to the ten codes of the appendix), the severity 1 - 5 and the measures tried, in the order they were tried.
  • Occurrences: every cavity and every fault zone met, also in successful holes (they train Model H), and every other problem with the measures used and whether it was solved. The last measure of a solved occurrence is counted as the one that solved it; a measure of an unsolved occurrence or of a failure counts as not solved. A cavity met without problems is recorded with no measures.
  • Geology: the logged rock code (mapped to a rock class by the rock-code table) and the formation name (its card). Log the bedding angle to the core axis where possible - it is the incidence angle of the past hole; without it the hole inclination is used (flat bedding). Mark broken zones.
  • Hole size and bit: one row per interval; each size reduction normally marks a casing point. Do not move a size reduction made because of a failure before the failure depth (leakage, spec 5.9).
  • Runs: one row per core run (1.5 - 6 m). Per-run values are needed for the live warnings (rules R1 - R4, Model B); per-shift or per-hole values support only the pre-drill risk. Record return %, rod drop, bit load and torque from now on (spec 3.3): rules R6 - R8 use them at once, the models once about 100 holes have them.
  • Free text measures of old reports are mapped once to the measure codes while digitising.

3.7 Preparing the geological model

  1. Export the model as surfaces: one Surpac DTM (+STR), DXF or GOCAD TS file per object - horizons (contacts), unconformities, faults, topography, and formation solids if available.
  2. Open them in the workspace (or Import geological model / Import fault surfaces, which ask or set the role) and set each layer's Role (Properties panel or Geological Model window).
  3. In the Geological Model window, check the contacts are in stratigraphic order and name the units between them exactly as the formation cards (a status column shows whether each unit has a card). A horizon named like horizon_H2_U2-U3 names the units above and below automatically.
  4. Set the error band: u near / far, the distance counted as far, the fault damage zone half width and the widening per variable unit, and the workspace's area (its site sheet). Model control = the collars of the workspace's drillholes and of the finished holes of the area.
  5. The settings are stored in <workspace>\drillrisk\geomodel.json; the roles in the workspace file.

3.8 Building the training table

Every finished hole (success or failed) is resampled into 1 m rows from the collar to its final or failure depth (spec 5.1). For each row the features of section 3.9 are computed from the hole's own logs (past holes have no geological model) and the labels are set:

  • Model H: cavity = 1 if the metre overlaps a cavity occurrence; fault = 1 if it overlaps a fault zone.
  • Model A: 1 in the metre of the failure for its family, 0 in every metre above; rows below a failure are not used.
  • Model B: 1 in the last 6 m before the failure (the precursor window), for rows with run data.

Training with noise (spec 5.6.1). The models must later run on the approximate model geology, so every past hole is also added a second time with noisy geology: each logged contact is shifted by N(0, 6 m) (kept inside its neighbours), units thinner than 6 m are dropped with probability 0.08 (formation missing in the model), the rock class is swapped with probability 0.05 by the mismatch table (dolomite ↔ limestone, sandstone ↔ quartzite, siltstone ↔ shale, marl → limestone), and the incidence angle gets N(0, 5°) noise.

Leakage control (spec 5.9). The geology log of a failed hole ends at the failure, so the base of the unit the hole stopped in is unknown: its distance-to-base, thickness, relative position and thickness anomaly are set to missing, and Models A and B use only the distance below the top of the unit. Size reductions and measures made because of a failure are not used for the metres above it.

4. Rock property calibration

Most drilling failures are controlled by the mechanical behaviour of the rock: strong fine-grained rock glazes diamond bits, abrasive rock wears them, foliated rock and strong / weak bed boundaries deflect the hole, weak and swelling rock caves and sticks the rods, soluble rock hosts cavities. The system therefore describes every metre by the properties of its rock class, kept in the editable table risk_rock.

4.3 How the properties enter the features

  1. The logged rock code is mapped to a rock class (table risk_rock_code; codes not listed are matched by name, e.g. 'dolomite').
  2. The class gives UCS, CAI, Young's modulus, brittleness (UCS / tensile strength), anisotropy, solubility, porosity and density of the metre, and the strength / abrasivity classes.
  3. If the rock is the main rock of the formation card and the card has a lab UCS / CAI, those replace the class values. The card also gives carbonate share, karst, swelling clay, bedding style and thickness range.
  4. The strength contrast with the unit above, log10(UCSabove / UCS), describes hard-over-soft contacts (deviation, rod failure).

4.4 Calibrating with laboratory and drilling data

  1. Map the rock codes. Check that every rock code of your logs is in Drilling Records → Rock codes with the right class; add classes for rocks not listed (Rock properties → Add row) with their properties.
  2. Laboratory tests per formation. Uniaxial compressive strength (ISRM suggested method; at least 5 specimens per formation), or point-load index Is(50) converted with UCS ≈ k·Is(50), k = 20 - 25 (calibrate k on a few UCS tests of the same rock); Cerchar abrasivity (ASTM D7625, 5 scratches per sample); density and porosity. Enter the medians in the formation card (UCS (lab), CAI (lab)).
  3. Class-wide changes. Where your rocks differ systematically from the defaults (e.g. strongly silicified dolomite everywhere), edit the class in Rock properties: the typical value is used, min / max document the range. Blank cells fall back to the default.
  4. Check against drilling. ROP of successful runs falls with UCS (approximately ROP ∝ UCS−0.5 at the same RPM and bit); bit life in metres falls with CAI. Plot the median ROP per formation (Risk Prediction uses the median ROP per rock class as 'normal ROP') against the UCS you entered; a formation far off the trend usually has a wrong class or lab value.
  5. Retrain the models (Models → Train now) after any change of rock properties, rock codes or cards, and compare the validation scores with the previous version (the versions stay available).
Note. The rock table is shared by all areas of one project database. Changing a property changes the features of every past hole of that rock class - which is the point of calibration, but it requires retraining.

5.2 Training procedure

  1. Load all records; apply the database's rock properties, rock codes and measures.
  2. Build the training table: every finished hole as logged, plus one noisy copy (section 3.8).
  3. Model H, out of area: for each area, fit H on the other areas and predict it - these probabilities become the stacked features of A and B. Then fit the final H on all holes.
  4. Model A per family on all rows; Model B per family on the rows with run data.
  5. Record the feature ranges (for the outside-experience flag R-M04), the cavity statistics by rock class and contact (reason R-K02), the median ROP per rock class and the severity weights.
  6. Validation leave-one-area-out (5.3) and tuning of the alarm thresholds.
  7. Save as <workspace>\drillrisk\models\models_vYYYYMMDD-HHMM.json (LightGBM model text + settings + scores) and make it current. Every warning saved later carries this version (spec 7.4).

Start it with Risk Prediction → Models → Train now, or .venv\Scripts\python.exe tools\train_models.py <workspace>. Retrain monthly or every 10 new finished holes, check the scores, and keep the older version current if the new one is worse (double-click a version in the Models window).

6. Predicting failure probability and suggesting measures

6.1 Ongoing drillhole

Risk Prediction → pick the hole → Predict. The chain (dfpredict\risk\predict.py):

  1. Path. The trial paths from the design and the surveys entered so far (section 2.2), to the planned depth + 60 m.
  2. Ties. Contacts logged so far are compared with the model's along the drilled path; the offsets shift the contacts below and narrow u (R-M02); a mismatch at the bit widens u (R-M01) (section 2.4).
  3. Geology along every path. Above the bit the logged units; below it the model units with the trial's offset; incidence angle from the model bedding; fault crossings ± the damage zone.
  4. Features per metre and path (section 3.9); hole sizes and bits as recorded (the last ones continue); RPM and flow ahead = medians of the last 3 runs.
  5. Model H → Model A per family; the area correction cf; mean over the paths.
  6. Model B (when runs are entered) for the next 10 m: the index there is at least the level of the precursor probability.
  7. Rules R1 - R8 on the runs and surveys; a rule triggered on the last run raises the level from 3 m above to 10 m below the bit to at least its own level (Yellow 0.20, Orange 0.45, Red 0.75).
  8. Levels per metre: the highest family index: Green below 0.15, Yellow 0.15 - 0.35, Orange 0.35 - 0.60, Red from 0.60.
  9. Zones: consecutive metres at Yellow or above, drawn from (top − u) to (bottom + u); precautions start at the top of the band. Status: Drilled / At bit (within 10 m of the bit) / Ahead.
  10. Reasons and measures per zone; P(reach target); the danger over any depth range; hole-level messages.

Reasons

For every zone the SHAP values of each family's Model A over the zone's metres are averaged; the features with the largest positive contributions are mapped to reason codes (e.g. carbonate share, karst, distance below the top of the carbonate, stacked cavity probability → R-K01; clastic-over-carbonate contact, site sheet → R-K02; fault distance → R-F01; stacked fault-zone probability → R-F02; incidence angle, foliation → R-B01; strength, abrasivity, bit → R-L01; swelling clay → R-C01; depth / rated depth → R-H01; drilling response → R-D..). The families of a zone take turns, so a zone of karst and instability shows the best reasons of both (up to 4). A triggered rule's message comes first. Each reason is a pre-defined sentence filled with the zone's values (appendix).

Measures

  1. Candidates from the decision table (spec 6.2, appendix) for the zone's failure codes and level: Yellow - watch; Orange - prepare (plus Yellow's); Red - act (plus Orange's and Yellow's), and the response measures 'if the event starts'.
  2. Filters: casing / size-reduction measures only when a smaller size exists and casing is on site; re-planning only before the zone is drilled; fluid changes only when that fluid is on site.
  3. Evidence ranking: cavity / loss / caving / casing measures by their solved rate among the 20 most similar past occurrences where they were tried (similarity: 2 × different rock class + different contact type + |Δdepth| / 200 m); operating-window measures (M-OP-01 - 03, M-OP-07, M-BH-03) filled with the 25th - 75th percentiles of RPM, flow and ROP of successful runs in the same rock class (formation, hole size, bit type where enough data: ≥ 20 runs from ≥ 3 holes), excluding runs within 20 m above a failure; everything else by the expert order of the measure library.
  4. Order: data-ranked measures with at least 3 uses first (highest solved rate first), then operating windows, then expert order; the top 3 prevention and top 3 response measures are shown, each with its evidence tag ('Data: solved 7 of 9 similar cases', 'limited evidence', 'Data: settings from 142 successful holes', 'Expert rule').

Hole-level messages

  • R-M02 contact tie, R-M01 model mismatch, R-M03 far from model control (collar farther than half the 'far' distance), R-M04 outside experience (a feature ahead outside the range of the training data: thickness, carbonate, hardness, abrasivity, depth, height above water table, site sheet values), the area correction, and the path summary (build / turn rate, spread at the target).

7.6 Daily use for a hole being drilled

  1. Before spudding: register the hole (collar, design, rig, casing and fluids on site); Predict; print the pre-drill register (Report); agree casing points and materials on site from the Orange / Red zones.
  2. After every run: enter the run (Next run), any event, the quick geology; after each survey (every 30 - 50 m, 10 - 20 m in trajectory-risk zones) enter the station; Predict again (the next 30 - 50 m are rescored).
  3. Follow the measures of the zone ahead from the top of its band; record what was done and whether it worked (Record event) - these outcomes turn expert-ranked measures into data-ranked ones.
  4. If the hole is abandoned: Record failure. When finished: set the result and the final depth; the hole joins the training data at the next retraining.
